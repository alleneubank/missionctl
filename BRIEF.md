# BRIEF — mission-control surfaces

> Law doc for mission-control surfaces, present-tense, no narrated history — git is the changelog. The Boundary and ratified Decisions amend only with human confirmation; the driver appends provisional Decisions, marked and dated. Working memory lives in the campaign's `LOOP.md` State, not here; floor waivers are dated Decisions below.

## Bar

Mission control is shippable when an operator can trust one compact projection to say what outcome is being pursued, what evidence is red or stale, and what human action—if any—is required next.

## Dimensions

- Semantic fidelity
- Portability
- Actionability
- Degraded-state honesty
- Reviewability

## Floors

- Semantic fidelity: schema and reducer fixtures cover every declared kind, lifecycle state, attention transition, evidence compatibility rule, and freshness boundary; only admissible evidence changes a rubric state.
- Portability: the release archive installs the same executable bundle on supported fleet platforms, structured consumers preserve the representative fixture's golden JSON, and direct human pass-through surfaces preserve canonical text exactly.
- Actionability: text output groups by attention class and then mission kind, preserves mission identity and red rubric IDs, and never prints a cross-mission score.
- Degraded-state honesty: malformed, stale, unavailable, and untyped sources are explicit in output and produce a non-zero `check` result where the authority is invalid.
- Reviewability: a fresh, disinterested reviewer briefed with this law and the specification reports no major-or-higher finding; review capacity is a campaign field rather than a global size limit.

## Oracle

The objective oracle is the repository harness over hand-written fixture expectations and cross-consumer goldens. The subjective oracle is a fresh-context reviewer that did not author the implementation, receives the specification, this brief, verification output, and declared deferrals, and grades on its own severity scale with `major` as the blocking floor.

## Never

- Never infer mission success from campaign status, activity, token use, issue count, age, or code volume.
- Never let incompatible, expired, or unknown evidence keep a required rubric item passing.
- Never merge successive campaign journals into one `LOOP.md`.
- Never hide malformed, unavailable, or legacy state behind an empty success.
- Never duplicate the mission's strategic rubric in this quality law.

## Boundary

The human authorizes each publication or tracked-ref merge and ratifies changes to this Boundary or existing ratified Decisions. All local implementation, validation, deterministic rehearsal, and preparation of publish prompts remain interior.
